# Security Policy

## Supported versions

Security fixes are applied to the latest published release. Users should upgrade
before reporting a problem that is already resolved in a newer release.

| Version | Supported |
| --- | --- |
| 1.x | Yes |
| 0.x | No |

## Reporting a vulnerability

Please do not disclose a suspected vulnerability in a public issue, discussion,
or pull request. Use GitHub's **Report a vulnerability** button on the
[Security page](https://github.com/echerrman/Elios-Colorizer/security) to submit
it privately.

Include the affected version, operating system, reproduction steps, potential
impact, and any suggested mitigation. Remove flight footage, facility names,
customer information, credentials, and other sensitive data before attaching
diagnostics.

You should receive an initial response within five business days. Confirmed
issues will be investigated privately, fixed on a coordinated timeline, and
published through a GitHub security advisory when appropriate.

## Scope

Security reports may cover the desktop application, its packaged dependencies,
release artifacts, build workflows, and handling of local flight data. General
bugs and feature requests belong in the public issue tracker.
